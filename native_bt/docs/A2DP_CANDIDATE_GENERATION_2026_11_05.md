# Requested-format A2DP candidate generation — 2026-11-05

The new generator turns an explicit family/rate/channel request into a mutually supported CIE and then uses the existing exact matcher. It covers current supported SBC, AAC, aptX/HD/LL, LDAC, Android Opus/Opus05 and LHDC V5 layouts. Family comes from actual codec/vendor identity, never an Android enum or SEID number. This is requested-family generation, not automatic cross-family ranking, reconnect or a default caller.

Rate and channel count are required and exact. Nonzero family-specific requests are not silently relaxed. Zero option fields select documented mutually supported defaults. Existing raw-CIE matching remains available for explicit policies outside this generator; unknown vendor extensions are not silently trimmed.

SBC selects mode, blocks, subbands, allocation and bitpool. Default bitpool is bounded by both advertisements and the actual SBC frame parser's mode/subband, size and profile-rate rules. Explicit maximums that fail that chosen-frame policy are rejected, not reduced. The [primary A2DP1.4.1 specification](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/a2dp_v1-4-1_1752513648/A2DP_v1.4.1/out/en/index-en.html) defines frame bitpool limits of 16×subbands for mono/dual and 32×subbands for stereo/joint. The existing parser also enforces mono320kbps/two-channel512kbps. These checks describe this generated-frame policy; they do not alter the raw exact-CIE API or existing incoming codec negotiation.

AAC selects supported MPEG4/2LC, exact frequency/channel fields, explicit CBR/VBR policy and a mutually bounded maximum bitrate. AptX variants retain their actual identities and supported base-layout fields. LDAC selects frequency/channel mode only; it does not fabricate a negotiated quality/bitrate or source input-depth field. Android Opus and Opus05 select supported durations; Opus05 location and bitrate use the existing raw protocol field without guessed units, and reverse audio remains unadvertised. LHDC uses explicit depth, supported feature bits and numeric min/max bitrate tables, not a blind AND of ordinal encodings. A requested 1000kbps maximum unsupported by a peer does not silently become 900. A negotiated maximum is not a measured encoded bitrate or an encoder-quality command.

Generated parameters always pass local and peer validators through the exact-format matcher. No decoder is constructed, no frame is decoded and no packet is transmitted. All input/output views are disjoint/caller-owned; failure/no-space returns no partial configuration. There is no heap, persistent task or default operation instance.
