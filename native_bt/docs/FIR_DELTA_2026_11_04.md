# Exact FIR coefficient-delta candidate

The [full-output reason trace](RF_RENDER_REASONS_2026_11_04.json) measured
1732.91 us per full 128-frame render unit at 96 kHz, versus a 1333.33 us budget.
The descriptor fault was order (expected index 0, observed 2, 1024 bytes), with
zero shape/map errors. DMA EOF gap reached 17202 us. Input RTP sequence and HCI
ingress rejection counters remained zero. Three CPU0 starvation warnings were
recorded. This is an output failure, not a playback pass.

The [controller-off compiler comparison](FIR_COMPILER_REFERENCE_2026_11_04.json)
passed 27 three-way sample/full-state cases. O3 remained best at zero fractional
phase; Os was only slightly better during drift. The production compiler policy
is unchanged. A global switch to Os would regress the integer-phase case.

## Arithmetic invariant

Existing tables are unchanged: regeneration adds one bound macro and no changed
coefficient values. The maximum absolute difference between adjacent phase rows
is 10373296 (96 taps), 10371417 (48 taps), and 10365512 (24 taps), all < INT32_MAX.
Phase selects rows 0..127 and their successor, so these cover every coefficient
pair used by the FIR.

For `r` in [0, 2^25), interpolation is exactly
`first + trunc_toward_zero((next-first)*r / 2^25)`.
The difference therefore fits signed int32. The signed int64 product remains
unchanged in precision, division and rounding. The resulting offset lies between
zero and the difference; adding it to first stays between the two valid int32
endpoints. Neither the subtraction nor final int32 addition overflows.

The guarded candidate gives the compiler a signed 32-by-32 product instead of
a generic 64-bit difference/product/addition. Tables without a suitable bound,
or `DBT_RESAMPLER_FORCE_WIDE_DELTA`, retain the original arithmetic. No sample,
coefficient, tap count, rate, bit depth, or filter-state behavior is reduced.
No persistent RAM is added.

## Validation scope

The actual optimized and forced-wide paths each pass 150000 128-bit-integer
output/full-state oracle cases under ASan/UBSan. The test also verifies the
generated bound against every adjacent table entry and checks interpolation
endpoints and rounding boundaries. The actual four-way runner passes all
27 case groups against the original O3 wide reference at zero and +/-500 ppm.
All 180 portable host groups pass.

The target comparison now includes that original O3 wide reference plus the
candidate at Os/O2/O3, with rotating order and first/steady timings. Its finite
measurement deadline is 12 seconds and owner deadline 20 seconds; speed remains
reported separately from correctness.

## Target result

The [candidate result](FIR_DELTA_RESULTS_2026_11_04.json), image
`0cf4febcf6b617d77c820759cce1893e256748d51c2072aa63c740c606d97568`,
passed all 27 four-way case groups (108 result records), including complete
PCM and state equality. Paired original/candidate O3 comparisons across three
trials show **24.5–27.4% less elapsed work during fractional phase**. Zero-phase
changes are under 0.7%, treated as effectively unchanged. O3 remains the product
policy; O2 regressed the 48 kHz zero-phase case and is not selected.

This is a FIR-kernel improvement, not an entire-pipeline speedup or a headroom
guarantee. The maximum-LHDC pipeline still supplied only 15/96 packets and
retired 13 before queue saturation; DMA did not begin. The pre-DMA integer-phase
path gains little from fractional interpolation work. The DSP and remaining
conversion/render costs still exceed the frame budget. The whole diagnostic
therefore returned failure despite the FIR equivalence pass. Buffers were
reclaimed and the released baseline boot was verified without fatal markers.
The full audio/headroom gate remains open.
