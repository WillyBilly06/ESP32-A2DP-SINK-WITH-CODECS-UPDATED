# ERTM channel storage and provider callback ownership

Comparison uses the clean BTstack checkout at 9edb5d82ea6ec4466a393415d65030929330acdf, especially l2cap.c:644–721 (validation and channel buffer setup) and :1297–1324/:5296–5301 (release notifications and teardown). Reference code is not integrated.

The owned channel frame path previously allocated peer-MPS+6 bytes when preparing each I/S frame and freed them at commit/cancel. The reference carves channel storage during setup. The owned path now reserves its same encoded-frame capacity after successful engine initialization and before announcing OPEN, retains it through commit/cancel and MTU-only reconfiguration, and releases it once at channel disposal. Setup failure retires the channel without announcing OPEN.

MPS remains bounded by DBT_ERTM_MAX_MPS=65529, so the six-byte Enhanced Control/START length/FCS allowance fits uint16_t. Current negotiation clamps initial peer MPS to manager maximum_mtu−6; accepted reconfiguration rejects MPS/window/MaxTransmit changes. A larger MTU therefore cannot overrun the retained encoded buffer. Frame encoding, FCS, borrowed SDU/ACK lifetime, ACL admission and timer policy are unchanged. Prepared bytes still remain immutable until the runtime commits or cancels that frame.

Manager allocation/release hooks previously bypassed the non-reentrant callback flag. The ERTM engine had the same gap for its providers. New small owner-only wrappers preserve/restore the existing flag around every such call, preventing recursive close/poll/send from invalidating a provider's caller. Runtime abort intent still uses the prior deferred owner finalizer. Callback-safe channel close intent remains allowed. No flag, task, lock or queue is added. Reinitialization remains a caller obligation after close and callback unwind.

This removes allocation/free of the encoded buffer per frame. It does not remove the engine's per-SDU window metadata allocation or segmented RX allocation/release, and does not establish all ERTM paths as allocation-free. Active ERTM retains an additional peer-MPS+6 payload plus allocator overhead between frame pins, including when no frame is pending. Peak encoded working capacity is unchanged; idle Basic A2DP has no such buffer. This is not an established cause or fix for the reported Basic A2DP codec underruns.
