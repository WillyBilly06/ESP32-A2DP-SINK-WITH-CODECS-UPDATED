Local Start now uses the same operation slot as Configure/Open. Its source entry requires the exact current nonzero media lifetime, configured decoder and Open state. The product adapter validates both full channel keys before acceptance. Start command bytes remain copied and blocked until worker READY. Peer Accept commits STREAMING before the normal observer callback and before another media packet can be dispatched. Generic non-Configure acceptance no longer implicitly means Open; legal operation/state combinations are explicit.

Renderer preparation can already have been accepted when cancellation or peer rejection occurs. This must not be handled by the Open procedure's retain-configuration branch. The new cleanup submits a serialized local SUSPEND job with its own token, enqueue/result flags, BUSY count and deadline. Only its READY receipt proves rollback; a rejected enqueue/receipt, FATAL or deadline closes the affected profile and drains DROP. The decoder configuration and established media remain usable only after successful rollback. Cancellation before worker acceptance requires no compensation. An accepted preparation job also requires rollback after a REJECTED receipt: that result alone does not prove renderer quiescence. A post-wire cancel with uncertain peer state retires the profile rather than guessing rollback at the peer.

Peer Abort supersedes rollback with DROP and releases older accepted jobs before reuse. Binding/job identity checks prevent an old receipt from completing the new job. Late preparation and rollback receipts are retained as separate metadata even after supersession, without changing the newer pending job. FATAL preparation during live rollback retires the profile. Receipt deadline fields describe when the owner observed acknowledgment; they are not measured decoder execution times.

The result keeps wire outcome, peer error, rejected Start SEID, worker preparation, rollback and DROP admission/receipts/timeouts separate. A Start rejection detail is not mislabeled as a codec service category. Incoming Start/Suspend list validation still identifies an invalid endpoint before reporting a local-operation collision. No callback waits for a worker or I/O, no retry spin or new task is added, and provider wakeups/deadlines drive pending work.
