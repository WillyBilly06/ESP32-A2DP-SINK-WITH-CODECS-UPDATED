# Asynchronous ordered-request A2DP ranking — 2026-11-05

The new caller-owned rank operation drives Discover and version-appropriate Get[All]Capabilities on an existing exact signaling lifetime. It evaluates an explicit ordered list of format requests with the current generator/matcher, copies its best normalized proposal and returns a result. It does not configure a stream, start audio, write app preferences or choose a default remembered peer.

Lower request index is the caller's priority. Equal priority keeps first discovery order; unspecified codec defaults are not secretly ranked as global acoustic/encoder quality. Explicit rate/channel/depth/bitrate-bound constraints retain generator semantics. Only the supplied request list authorizes a lower format choice. All eligible advertised audio Source endpoints must be assessed. A rejected, truncated, malformed or otherwise failed capability query prevents successful partial ranking, even if an earlier candidate matched. Unsupported requested vendor layouts likewise return incomplete capability assessment rather than silently dropping that requested feature. In-use/non-audio/Sink SEPs are counted and skipped.

Each owner iteration performs one query transition, at most four cheap SEP skips, or one format evaluation. Wire waits use the existing signal/bearer and controller readiness; BUSY submission owns nothing and only becomes immediately runnable when the local signaling slot is free. No callback waits or unbounded processing loop is added. Overall timeout stops new work and requests cancellation; terminal completion can wait for the accepted query's separate response/timeout/clear fence.

One embedded query object is reused only after its matching terminal result, preserving its nonrepeating serial. Discovery/capability buffers and request/endpoint data remain caller-owned and disjoint through terminal result. Context has a 32-byte copied best proposal; it does not retain every peer capability body. Query callback completion is distinct from the signal's separately pinned TX storage. Stale/error tokens never release an accepted query. A lost accepted token requests affected signaling retirement and retains context in FAULT_RETAIN; it does not fabricate safe release or an immediate polling spin.

Result fields separately retain discovery, last capability and best capability receipts, last/best generation, submit/cancel results, visited/eligible/assessed/skipped/evaluation counters, selected request index and complete-assessment flag. A proposal view is exposed only on terminal complete SUCCESS and remains inside the caller context until reuse/free. No result implies peer acceptance or reservation; actual Set Configuration remains a separate procedure.

Owner integration adds explicit begin/cancel/result APIs, normal poll/wait routing and restart barriers. Initial begin requires an idle exact signaling session. If the peer takes over stream configuration, ranking cancels and returns CONFLICT after its query fence, preserving the incoming feature path. Signaling change and restart cancel ranking without early release. Internal lost-query faults retire only the still-associated signaling profile. Root result acknowledgment detaches its caller-context route before the caller may free it.

No default instance or automatic begin is enabled, so no new ranking query runs at boot.
