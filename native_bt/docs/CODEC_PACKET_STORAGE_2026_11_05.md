# Configured-lifetime Opus reassembly and LDAC staging — 2026-11-05

The Opus adapter previously allocated/grow-copied/released its encoded reassembly buffer in media handling and freed it on expiry/reset. This introduced general-heap work on the decoder core while fragmented packets arrived. The finite capacity-doubling loop was bounded; the problem addressed here is allocator activity and repeated working-storage ownership, not an infinite wait.

A successful Opus open now reserves the existing 6144-byte reassembly limit in one separate codec-owned allocation. Setup failure is rejected before READY and generic codec-open cleanup releases both allocations. Close frees the fragment allocation and original aligned codec/PCM/scratch allocation exactly once. Media, reset, expiry and partial-packet clear only reset cursors, preserving storage. Since a reserved pointer is always present, active-fragment checks and the 100 ms deadline now use fragment_size; pointer presence must not keep an idle instance runnable or repeatedly reset it.

First/last/count ordering, RTP sequence/timestamp/SSRC validation, malformed/over-limit rejection, expiry origin and PCM retirement are unchanged. The final assembled input is consumed by the guarded decoder before logical clear. Pending PCM points into the separate persistent PCM region, not the encoded assembly buffer. New media remains BUSY until PCM is retired. A partial packet expires without heap operations. The 1800-byte × 8 receive queue and 6144-byte logical reassembly maximum are unchanged; there is no new task or queue.

The pool is deliberately separate: the main codec workspace allocation size/largest-block requirement is unchanged. Every configured Opus instance now reserves 6152 accounted bytes (6144 payload+8 allocation header), including unfragmented streams. This consumes more steady Opus RAM than the former zero-buffer common case. It is configuration-specific and released before another codec is constructed; no static pool is reserved for an idle host or retained by LHDC/LDAC/SBC. Startup checks construct temporary Opus instances and release their pools. During the former last growth 4096→6144, both old/new buffers temporarily coexisted; that overlap and prefix copy no longer occur. No lower overall RAM or measured speed improvement is claimed.
