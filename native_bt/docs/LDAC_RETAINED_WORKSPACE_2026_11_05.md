# Retained LDAC working storage and gap reset

The previous LDAC reset called ldacBT_init_handle_decode, which closes the SDK decoder and allocates new AC, ACSUB and AB working blocks. The common worker invokes reset on sequence/SSRC discontinuity and decode rejection, including a gap caused by a locally full input queue. Repeated recovery therefore entered the general heap. This was confirmed from the pinned source; no claim is made that it caused every reported underrun.

The new product keeps the original SDK reset/initialization procedure and reconstructs the same zero-initialized working objects inside caller-owned storage. Capacity is calculated from the selected 128/256-sample configuration, mono/dual/stereo channel/block counts and the generated AC/ACSUB types, using the SDK eight-byte allocation rule. The arena follows the existing PCM and padded encoded scratch in the same session allocation. Work capacity is 2368/4624/4736 bytes for mono/stereo/dual at 128 samples, and 4416/8720/8832 at 256 samples. No maximum-rate global pool is added.

The SDK caller-memory path originally advanced p_mempos without bounds or clearing. Its generated allocator now delegates exclusively to the owned checked allocator: it validates multiplication/alignment, pointer membership, remaining capacity and address arithmetic before clearing or advancing. Each successful block is zeroed, reproducing the old calloc state. There is no working-block heap fallback. External allocation is enabled only around initial creation of the two SDK handles. Successful or failed reset does not call that allocator; retained resources after a failed reset remain owned until the worker’s explicit DROP/close. Initial open failure is still reclaimed by generic codec-open cleanup.

Teardown first closes the SDK decoder while its nonnull caller-memory cursor suppresses per-block free. It then detaches p_mempos and all arena pointers from the closed library handle. This matters because SDK ldaclib_free_handle otherwise skips freeing a handle with p_mempos set. The two separately allocated handles and the session allocation are then released through their original accounted provider. Partial-initialization free calls on arena addresses are no-ops; no interior pointer reaches the heap. PCM is rebound after every reset, and existing worker PCM-retirement/generation gates remain mandatory. No codec/frame validation, rate, precision, bitrate, queue geometry or affinity is changed.

Allocation-relevant memory_ldac.o.c, ldaclib_api.o.c and ldacBT_api.o.c are now source-pinned alongside the existing generated files. All ten generated units are checked before build. The core remains independently authored; this uses the project’s existing standalone SDK codec, with no BTstack integration.

Compiler-only Xtensa ABI measurement reports state=84 bytes (aligned prefix 88), AC=196, ACSUB=8, AB=112 and handle sizes 132+80. The layout probe is neither linked nor executed. Full ccache compilation and strict C11 Clang analysis pass. Whole-image text grows by 344 bytes; aggregate data and BSS are unchanged. Runtime heap and startup evidence are recorded after deployment. Neither static analysis nor automatic codec startup checks qualify repeated RF gaps, allocation-failure recovery, long playback or timing gains. Separate functional/packet-injection/playback campaigns remain held by the user.

COM6 deployment b150c844ba744f3f8d00dbef59044a56372c0ff3311a4f087ab4f8806634cdb3 is readback-verified at ota1 0x390000, written at 921600 and verified at 230400. Owned selection stays VALID and the original application is preserved. Startup reports ready with no watchdog/backtrace, and all 37 automatic codec cases pass. The six existing LDAC cold cases show tracked allocation peaks falling by 33 bytes for mono and 61 bytes for stereo/dual, including checker instrumentation. All close without remaining tracked allocations. Idle heap remains 138112 bytes, minimum 69740 and largest block 110592. Repeated-gap behavior and performance remain unqualified.

Existing build/regression contracts were updated for ten pinned units, required workspace symbols and zero provider calls across suspend/restart with a provider failure armed. Open-allocation failure coverage remains. Those harnesses were not executed; only their syntax was compiled. The subsequent source-only rebuild is bit-identical to the already readback-verified image, so no second flash was needed for the contract edits.
