# Exact bounded block-DSP experiment

The first-drop trace locates loss at the full decoder queue, with the consumer
path exceeding its frame budget. This experiment addresses repeated filter
state/coefficient traffic. The default renderer still uses the existing
per-frame kernel. The bounded API is compiled with `FIXED_DSP_BLOCK_API`, and
the opt-in finite renderer path is selected by `-BlockDsp`.

The new owner-only API accepts at most 128 interleaved stereo frames. It rejects
invalid bounds, missing storage and misalignment without changing state. It
uses a fixed 1024-byte split-output scratch array on the caller's stack, with
no heap allocation, task, queue or persistent
DSP state added. Actual target stack/code costs still need measurement.

## Preserved computation

Analysis visits input frames in their original order. The four EQ/compensation
sections then process one channel/block at a time. Stable sections reuse local
coefficients/history; identity sections retain exactly the final histories and
fraction reset, including a one-frame transition from a nonidentity section.

The initial stage-by-stage ramp candidate regressed on the target. The revised
API therefore processes the coefficient-ramping prefix with the original
per-frame kernel. Once all coefficients are stable, the rest of that block
uses reuse. Every coefficient value, remainder and ramp error is preserved.
Volume/flip/bypass ramps still advance per sample in the stable path. Crossover and
the three independent boost histories retain their computations. The final
per-frame pass advances volume/bypass/flip, blends, limits and scales in the
original left/right order. Control changes remain owner-only at block bounds.

The proven five-product int64 bound and carried Q28 fraction are unchanged.
Unproven/custom tables keep the original overflow-safe split sum. No filter,
tap, analysis stage, sample precision, clipping policy or coefficient ramp is
removed. The stable-channel helper explicitly uses O3 on GCC/Xtensa; the
diagnostic wrapper otherwise uses Os. This mixed selection is recorded, not
presented as a pure compiler-level comparison.

## Local evidence

Both proven and split-fallback builds pass 26624 blocks / 1691971 frames at all
13 supported rates under ASan/UBSan, without signed-overflow wrapping. Every
PCM sample and the complete DSP state match the existing per-frame path.
Coverage includes rapid interrupted controls, settling ramps, stable full EQ,
identity transitions with unequal old x/y histories, rail signals, general
int32 histories and variable block lengths 0..128.

The actual controlled comparison runner adds an Os block variant alongside Os
and O3 per-frame references. It retains the 18 full-EQ/bypass groups and adds
nine flat-EQ groups, producing 81 rows across 27 groups. Work order rotates;
PCM and full state are compared after every block. All host groups pass.
Existing profile/inline modes retain their 18 pairs and pass their host checks.
The actual image validator requires the new wrapper with final Os compilation;
mode/admission checks pass. These are not Xtensa speed measurements.

The default CPU-only comparison now has a finite 10-second case budget and a
23-second owner budget, matching the existing longer FIR allowance. This does
not relax a playback deadline. The diagnostic still returns to the pinned
released baseline and serial capture remains bounded at 35 seconds/128 KiB.

## Initial target result and revision

[The first target comparison](BLOCK_DSP_TARGET_INITIAL_2026_11_04.json) passes
all 27 groups / 81 variant rows with full PCM/state equality. Stable full EQ
improves by about 10–11%, and stable flat EQ by 31–34%, across the three rates.
At 192 kHz/flags9, paired median steady cost falls from 6.875 to 6.139 us/frame;
flat EQ falls from 4.904 to 3.244 us/frame. These are controller-off core1
kernel comparisons, not full render/RF timing.

Full-EQ coefficient ramps are nevertheless 9–10.5% slower in that candidate,
so it is not selected. The revision uses the original per-frame ramping prefix
and switches only the stable remainder to block processing. Both wide host
modes and all 27 actual comparison groups pass again after this change.
The [hybrid retest](BLOCK_DSP_TARGET_HYBRID_2026_11_04.json) again passes all
81 rows. Steady full-EQ gains are 12–13% and flat-EQ gains 33–36%. At 192 kHz,
flags9 steady cost is 6.011 versus 6.874 us/frame; flat EQ is 3.162 versus
4.904. Ramp cases range from about 0.2% faster to 1.6% slower. This removes the
large initial ramp regression, not every measurement difference. Its task
stack low-water mark is 5028 bytes. Both trials return to released firmware.

The initial target task retains 5220 bytes of its 8192-byte stack at its lowest
observed point; the linked block function's own entry frame is 1088 bytes.
Neither number is a complete future renderer-stack budget. The separate
pipeline still uses the original scalar renderer and fails before completing
its 96-packet comparison. It accepts only 512 source frames and never starts
DMA. The baseline returns with no fatal marker.

## Opt-in renderer connection

`-BlockDsp -PcmLoans -AsyncAudio` connects the exact API to the audio renderer.
Conversion/resampling fills at most 128 stereo frames on its stack, then DSP
processes that block and writes the existing output pages. Larger caller
budgets use successive bounded blocks, preserving the existing return-count
contract. Final mixing and publication retain their original ordering; a PCM
loan is not retired early. The staging array adds 1024 bytes to the renderer's
stack, nested with the block API. No heap working buffer or task is added.

All 108 real-core stream pairs (4096 input frames each) match the original
scalar/copied renderer under ASan/UBSan, including full DSP/resampler state,
16/24/32-bit input, mono/stereo, aligned/unaligned views, adaptive/linear clock
modes, +/-500 ppm, wraps, rapid controls and poisoned retired loans. Page
capacity/OOM/wrap/mix and numerical-format tests pass with block rendering.
The actual asynchronous provider also passes at 64/32/16 ms with block DSP,
including cancellation, stale IDs, DMA fault and restart fencing.

Mode guards require finite PCM-loan output. Image admission binds the receipt,
cache, main marker and both actual core compilation flags; deployment requires
explicit finite RF or pipeline mode with baseline return. I2S records expose
`block_dsp`. The all-codec/product build passes source/image/layout and limited
IRAM callback admission. [Source-matched local receipts](BLOCK_DSP_LOCAL_RESULTS_2026_11_04.json)
remain separate from target kernel timing.

Full-product runtime stack use, radio headroom, maximum-rate continuity and
feature parity remain open. A kernel gain is not a full-pipeline pass.
