## Implementation and controller boundary

The host publishes one immutable job to the existing general background worker. That worker calls `esp_coex_status_bit_set/clear`, publishes its result/timestamps/core and wakes the host. Each owner poll admits at most one job, and one strong atomic claim permits one worker execution. The owner reconciles newer streaming state only after consuming the outstanding result. There is no owner-side SDK call, wait, allocation or retry loop. No new task type, stack definition, audio buffer, codec arithmetic or affinity/priority policy is introduced.

Streaming SET0x10 is followed by a separate PAUSED CLEAR0x20; stopping clears both, matching the preserved SDK policy. Initial state clears both. Stable state produces no work. Errors publish failure, and token exhaustion fails closed. Storage stays alive through worker retirement. Builds without the product auxiliary-worker provider do not admit an unserviceable job or spin on it.

The public SDK calls can wait on the coexistence semaphore. Inspection of the exact linked library shows an indefinite semaphore wait; placing them on the existing background worker keeps it off host, decoder, renderer and ISR paths. That worker is lazy, so invoking it can allocate its existing stack. Static context size alone is not a bound on live RAM.

The first candidate sent the SDK's vendor opcode0xfc82 directly through owned HCI. COM6 returned Unknown HCI Command1. The SDK's [vendor-command boundary](https://github.com/espressif/esp-idf/blob/master/components/bt/include/esp32/include/esp_bt_vs.h) and local `controller/esp32/bt.c` show that this command is enabled only for Bluedroid/NimBLE configurations and advise applications against calling its private enable hook. The rejected command path was removed. The current public API path uses `esp_coex/lib/esp32/libcoexist.a`; no Bluedroid, NimBLE or BTstack host is linked and no private controller hook is called.

## Independent diagnostics and memory

Separate queued/completed/failed records retain token, operation, bit, API result, worker core and wall interval. Queue acceptance is not completion. The interval includes waiting/preemption. The coherent one-word `a2dp_coexistence_state` snapshot separately publishes known/applied bits, pending and failure. It survives event-ring saturation but does not reconstruct missing event timings. A full-ring app test exercises this distinction.

API success and these software-confirmed bits are not independent RF bit readback or proof of a radio scheduling improvement. Espressif describes the [scenario-status APIs](https://github.com/espressif/esp-idf/issues/12434) as inputs for upper-layer RF coexistence scenarios.

The mailbox is36 B on target, including its four-byte status publication. Alignment absorbs that added field: total DRAM data remains +396 B versus `77101dff5795`, including newly linked SDK constants. BSS and IRAM are unchanged; flash text +1448 B. Normal2x192 DMA and the31744 B PCM/DMA payload budget remain. These section sizes are not a runtime RAM improvement claim.
