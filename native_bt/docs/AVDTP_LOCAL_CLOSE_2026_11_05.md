The reference is BTstack commit 9edb5d82ea6ec4466a393415d65030929330acdf, src/classic/avdtp_initiator.c:349–359 and 607–620. Close is sent from Open/Streaming; Accept enters Closing and requests media disconnection. This independently authored host also owns a separate decoder/renderer worker, so transport and backend completion must be joined. No reference implementation is integrated.

Local Close now uses the shared caller-owned operation. Its owner adapter validates the exact signaling and live media handle/generation/CID/serial. The command is copied without a pre-wire worker job. Streaming media remains admitted while the peer has not accepted Close. Reject and known-unsent cancellation preserve the prior Open/Streaming state when media is still present.

Accept creates the primary CLOSE worker token/deadline and enters Closing. It requests media closure through the existing deferred profile event while the worker shuts down independently. Neither callback waits for the other. Configuration and caller context remain reserved until worker READY and normal media retirement have both arrived. The final owner step enters Idle, releases configuration and returns the terminal result. Pending worker or media work uses its provider event/deadline, not an immediate retry spin.

If media closes before the worker, the local Close path records closure and keeps configuration/Closing state. It does not use the ordinary handler that frees configuration immediately. If normal media closure arrives before the peer reply after wire release, the operation can still accept a later Close Accept and clean up correctly. A subsequent Reject/cancel cannot restore a missing channel and instead retires the profile. Abort supersedes through the existing DROP/reply/media lifecycle. Fatal/late/failed backend work and media deadline failures also retire the affected profile; shared ACL and other PSMs are preserved.
