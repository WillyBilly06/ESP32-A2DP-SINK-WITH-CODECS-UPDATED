## Bounded input-clock state

The generic codec worker now records its maximum forward half-range RTP timestamp step between consecutive16-bit wire sequences with the same SSRC, after size checks and before media-queue admission/codec decode. Raw/synthetic packets, sequence breaks, source changes and ambiguous/backward half-range steps cannot create a pair. Source epochs reset the snapshot on the first packet; zero tick steps and ordinary32-bit timestamp wrap remain valid observations. A tagged sequence word distinguishes no eligible pair from a valid zero step.

Five atomic words plus existing padding/target alignment cost24 static bytes in the full image. No packet/PCM buffer, task or dynamic allocation is added. The worker observer performs no timer/kernel query or wait; the existing probe trace hook timestamps sparse new maxima. A single host writer publishes an odd/even revision with explicit fences. The logger makes one sequence-check attempt and exposes incoherence instead of retrying. A sparse input_clock_max event is appended only for a new maximum. Its enum value is appended; existing timing IDs are preserved and the app explicitly routes the event to the host single-writer ring. Trace entry sizes do not grow.

The dedicated rtp_input_clock record contains the exact sequence/timestamp pair, SSRC, input epoch, observed/coherent flags and a raw-tick scope. It is explicitly not a loss counter or automatic decoder reset. Source rate/packet framing must be interpreted separately. No concealment, padding, time stretching or PCM mutation is introduced.

Actual generic-worker ASan/UBSan checks cover1800-byte/eight-slot ownership and saturation, the new pre-decode observation,16/32-bit wraps, epoch reset, raw-to-wire exclusion, zero steps, sequence/SSRC discontinuities, odd/sequence-wrap snapshot publication and queue-full ingress.
